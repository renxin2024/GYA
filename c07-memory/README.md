# C07 演示：三层记忆——上下文、短期、长期

一个演示「上下文窗口 ≠ 记忆」的最小程序：三层记忆架构 + 纯 Python 向量检索（零依赖）。

## 演示内容

1. **短期记忆（Working）**：用户自报"我叫张三"→ Agent 提取存入短期记忆 → 几轮无关对话后，模型上下文已"忘了"名字，但记忆补上——模型仍答对
2. **无记忆对比**：同样的问题没有任何上下文时，模型明确说"我不知道你是谁"
3. **长期记忆（Semantic）**：纯 Python 余弦相似度检索（中文 bigram 分词 + 停用词过滤），跨"会话"记住用户偏好/职业/主题
4. **Lost-in-the-Middle 效应**：长上下文中信息放中间 vs 开头（实测说明，详见正文）

## 它证明的事

1. **上下文窗口 ≠ 记忆**：模型本身不"记得"，全靠我们每次把历史塞进 prompt。塞不下的、塞在中间被忽略的，就是"遗忘"
2. **短期记忆 = 显式提取**：从对话中把关键事实（名字/偏好）提取成结构化条目，比全量历史更省 token、更抗干扰
3. **长期记忆 = 检索**：不检索的记忆等于不存在——向量检索让 Agent 跨会话"想起"用户是谁
4. **演示级分词有局限**：纯 bigram 对同义改写（"爱喝"vs"喜欢喝"）匹配不到——生产用真实 embedding 解决

## 常见坑

1. **Q: 向量检索用纯 Python 会不会太简陋？**
   A: 演示目的是理解"检索"这个机制本身。生产用真实 embedding（OpenAI/DeepSeek embedding API）+ 向量库（Qdrant/Chroma），原理一样但能处理同义词。
2. **Q: Lost-in-the-Middle 在 demo 里不明显？**
   A: 对，deepseek-v4-flash 对短 padding 抗性好（两头都答对）。这是论文在 100K 级长上下文上观察到的 U 型效应——demo 放它是为了让你知道这个坑，正文会引用论文数据（25-30% 差距）。
